# Scenario-tree experiment design

The scenario-tree layer was introduced to make the model v3 experiment design reproducible and interpretable across climate, technology, and stochastic uncertainty. Rather than treating each simulation as an isolated run, the framework defines each result as one leaf of a structured experiment tree. This makes the assumptions behind a result explicit before output metrics are compared.

The deterministic part of a scenario is defined by three dimensions: the climate analysis window, the climate pathway, and the technology case. The climate projections were organized into a structured scenario tree consisting of a historical baseline and three future climate windows under RCP2.6, RCP4.5, and RCP8.5. Each climate branch was combined with technology adoption assumptions and stochastic household realizations. This allowed climate, technology, and behavioural uncertainty to be separated and compared through consistent output metrics.

Each executable leaf adds one stochastic realization to the deterministic scenario. Scenario identifiers follow the format `{climate_window_id}__{climate_pathway_id}__{technology_case_id}`, while scenario-leaf identifiers follow `{climate_window_id}__{climate_pathway_id}__{technology_case_id}__{realization_id}`. These stable identifiers are used in generated configs, run directories, the run registry, standardized summaries, comparison tables, figure metadata, and audit reports.

The baseline branch is the historical current-stock case `baseline_1981_2005__historical__tech_current_stock`. Future branches combine the near-future, mid-century, and long-term windows with RCP2.6, RCP4.5, and RCP8.5 and with future-permitted technology cases. Climate-only future comparisons use `tech_frozen_stock` as the reference future technology case, because `tech_current_stock` is reserved for the historical baseline unless explicitly permitted otherwise by metadata.

The temporal treatment of 2050 is defined explicitly. Raw processed source files may overlap in 2050, but canonical analysis windows do not. The near-future canonical window ends on 2049-12-31, and the mid-century canonical window starts on 2050-01-01. Consequently, 2050 is assigned only to the mid-century canonical analysis window for cross-window statistics and comparisons.

For each scenario leaf, the generated run config records the climate forcing file, technology metadata, Belgian technology input YAML, stochastic seed, cohort size, output directory, and provenance sources. The corresponding inputs manifest and run registry record the same provenance in auditable form, including file hashes where available. Standardized per-leaf summaries then map raw model outputs into consistent metrics, and comparison tables compute deltas, percentage changes, and stochastic uncertainty bands only from these standardized outputs.

This design supports the separation of climate, technology, and behavioural uncertainty because each output can be traced back to four questions: which climate forcing was used, which technology assumptions were active, which stochastic seed and cohort generated the result, and which exact model configuration produced the output. The framework therefore supports reproducible scenario comparison without claiming that all enumerated leaves have been successfully simulated unless this is demonstrated by the run registry.
