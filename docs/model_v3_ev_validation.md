# Model v3 EV Validation Workflow

This workflow is a minimum defensible EV technology validation. It does not run scenario-tree leaves and it does not claim full household validation.

## What It Validates

The EV workflow validates the residential EV charging increment:

```text
Fluvius EV/no-PV representative profile
minus
Fluvius no-EV/no-PV representative profile
```

against the model EV charging profile generated by:

```text
model_v3.systems.distributed_energy.build_ev_charging_profile
```

This is a technology-level check. It asks whether the model adds EV load at plausible hours and annual energy scale.

## Command

```bash
PYTHONPATH=src python3 -m model_v3.validation.technology.ev.run_ev_validation \
  --repo-root . \
  --config config/validation/technology_ev.yaml \
  --generate-model-profiles \
  --force-model-profiles \
  --print-summary
```

## Interpretation

The Fluvius comparison is valid as a residential signature check, not as charging-session validation. Fluvius gives representative category profiles, not plug-in times, connection duration, or kWh/session.

KU Leuven house 1 has an EV charger in the metadata, but the public data is whole-house import/export and is confounded by PV and heat-pump operation. It is therefore secondary context only in this minimum workflow.

## What Is Still Needed

To complete a stronger EV validation layer, add an EV session or residential charging reference with:

- plug-in time distribution;
- departure or connection-duration distribution;
- energy per session;
- charger power distribution;
- weekday/weekend profile;
- enough households or sessions to estimate diversity.

ElaadNL is a useful European proxy. Belgian session-level data would be stronger if available.
