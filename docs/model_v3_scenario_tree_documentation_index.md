# Model v3 Documentation Index

This index separates maintained model-use documentation from generated evidence.
GitHub should contain the maintained guides. Simulation reports, registries,
summaries, figures, and validation artifacts are produced by the documented
workflows and are not substitutes for the guides.

## Maintained Model-Use Documentation

| Path | Purpose | Primary dependencies |
|---|---|---|
| `docs/model_v3_complete_model_handbook.md` | Complete architecture, inputs, outputs, scenario design, validation, caveats, terminology, and command reference. | Repository metadata and `src/model_v3/documentation/build_model_handbook.py` |
| `docs/model_v3_scenario_tree_design.md` | Technical design, directory contract, commands, and implementation workflow for the scenario-tree layer. | `config/scenario_tree/`, `src/model_v3/scenario_tree/`, `src/model_v3/scenarios/` |
| `docs/model_v3_scenario_tree_methodology.md` | Concise methodological explanation and interpretation guardrails. | Scenario configs, registries, summaries, and audit evidence |
| `docs/model_v3_scenario_tree_assumptions.md` | Auditable assumption register with rationale, affected outputs, checks, and limitations. | Scenario configs and validation policy |
| `docs/climate_pipeline.md` | CORDEX download, preprocessing, radiation conversion, and climate-input validation workflow. | `src/climate/` |
| `docs/model_v3_belgian_technology_integration.md` | Belgian technology-input runtime contract and carrier-resolved outputs. | `config/belgian_technology_inputs.yaml` and technology modules |
| `docs/heat_pump_implementation.md` | Heat-pump physics, COP, emitters, hybrid dispatch, assignment, and diagnostics. | Heat-pump and carrier-conversion modules |
| `docs/model_v3_pv_validation_triangle.md` | PVGIS, Elia, and Fluvius PV validation workflow and interpretation limits. | `config/validation/technology_pv.yaml` and PV validation runner |
| `docs/model_v3_ev_validation.md` | Minimum EV validation workflow, sensitivity, and remaining data requirements. | `config/validation/technology_ev.yaml` and EV validation runner |
| `docs/phase1_cooling_exposure_methodology.md` | Boundary between cooling-pressure indicators and unmodelled active cooling energy. | Climate and comfort metrics |
| `docs/output2_seasonal_monthly_demand_shift.md` | Interpretation guide for seasonal/monthly demand outputs. | Canonical comparison tables |

## Generated Evidence And Artifacts

| Path | Role | Generated by |
|---|---|---|
| `experiments/scenario_tree/manifests/` | Scenario index, run registry, and config/summary/comparison validation reports. | Scenario-tree creation, runner, summarizer, and validators |
| `experiments/scenario_tree/summaries/` | Standardized realization, scenario, and comparison tables. | `model_v3.scenarios.summarize_outputs` and comparison workflow |
| `experiments/scenario_tree_output34/` | Canonical selected hourly cohort evidence for Outputs 3-6. | Scenario runner and Output 3-6 post-processing workflows |
| `reports/scenario_tree_run_manifest.md` | Executed-coverage and provenance summary. | `model_v3.scenarios.audit_scenario_tree` |
| `reports/scenario_tree_validation_report.md` | Consolidated internal QA status. | `model_v3.scenarios.audit_scenario_tree` |
| `reports/scenario_tree_traceability_matrix.csv` | Traceability row for each latest-successful canonical leaf. | `model_v3.scenarios.audit_scenario_tree` |
| `reports/model_v3/validation/` | External and technology-validation reports. | Validation runners |
| `figures/scenario_tree/` and `figures/scenario_tree_output34/` | Data-derived thesis figures and metadata. | Figure workflows |
| `docs/model_v3_complete_model_handbook.pdf` | Local rendered handbook. | `model_v3.documentation.build_model_handbook` |

Generated artifacts may be ignored by Git because they can be rebuilt from the
code, configs, and local input/output data. Their existence and status must be
checked locally before making numerical or validation claims.

## Internal And Thesis-Only Notes

Supervisor feedback, temporary Codex briefs, audit scratchpads, claims tables,
and thesis-specific text fragments are not model-use documentation. They should
not be added to the GitHub documentation set unless intentionally promoted into
one of the maintained guides above.
